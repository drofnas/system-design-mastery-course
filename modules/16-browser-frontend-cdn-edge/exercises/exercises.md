# Module 16 Guided Exercises

Complete these with Northstar only. Freeze independent commerce decisions before
opening the answer key.

## EX-01: Interaction trace

Trace input, handler, promise microtasks, style/layout/paint, and next visible
feedback for the event filter. Mark evidence needed at each boundary.

## EX-02: One-control long-task pair

Design broken/repaired trials for a 240 ms filter calculation while preserving
input, useful result, browser profile, and DOM semantics.

## EX-03: Critical-path calculation

Calculate the transfer lower bound for 160 KiB over 1.2 Mbps with two 140 ms
dependent round trips. List at least five omitted costs.

## EX-04: Evidence classification

Classify field p75, five Playwright runs, a synthetic journey, and one trace.
State the decision each can and cannot support.

## EX-05: Route rendering matrix

Choose static, server, streaming, client, or island behavior for the four
Northstar routes. Record authority, useful HTML, interaction, and failure.

## EX-06: Streaming commitment

For `/events/:id`, name what must be known before the first byte and how late
weather/not-found failures appear after commitment.

## EX-07: Hydration identity

Define serialized fields and hashes required for the staff edit island. Predict
the result of a server/client version mismatch.

## EX-08: Public cache key

Build a bounded key from method, host, path, query, language, encoding, and content
version. Identify dimensions that should be normalized away.

## EX-09: Private isolation

Specify a two-session test proving `/staff/schedule` cannot hit or populate a
shared cache. Use pseudonymous identities only.

## EX-10: Failure and stale policy

Classify which Northstar routes may use stale-on-error, their maximum age and
visible status, and which must fail closed.

## EX-11: Interaction-state accessibility

Specify semantics, keyboard, focus, status, and recovery for loading, success,
empty, validation error, dependency failure, and retry states.

## EX-12: Evidence limit

Divide accessibility verification into deterministic DOM, automated rules,
manual keyboard/zoom, and assistive-technology evidence. State each limit.

## EX-13: Browser lifetime trial

Design a 30-navigation trial for listeners, timers, requests, detached DOM, and
heap checkpoints. Define the repaired pass condition without a universal MB limit.

## EX-14: Third-party admission

Write value, performance, authority, provenance, owner, kill-switch, fallback,
and exit requirements for the optional sky map.

## EX-15: Third-party failure pair

Design equivalent slow/blocked trials showing the public event journey remains
usable and accessible without the sky-map script.

## EX-16: Evidence integrity audit

Given F01–F08, list pair fields that must match, the one control that may differ,
raw evidence to freeze, and claims the lab cannot support.

## EX-17: Trace/privacy contract

Draw browser-edge-origin parentage. List allowed route/cache/render attributes,
prohibited private values, sampling authority, and cardinality/retention owners.

## EX-18: Architecture defense

Compare one modular portal, a portal plus BFF, and independently deployed
microfrontends/edge work. Defend one choice with route evidence, cost, ownership,
migration, rollback, dissent, stops, and reversal conditions.
