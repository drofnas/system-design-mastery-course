# Module 16 Explained Answer Key

These are Northstar examples, not canonical commerce answers. Alternative designs
pass when their contracts and evidence are defensible.

## EX-01–EX-02

The trace separates input delay, the filter task, promise microtasks, DOM writes,
render work, and next paint. The pair retains event data, query, result order,
profile, and semantics; only `yield_long_tasks` changes. The repaired version
shows the visible count before deferred enrichment and verifies identical results.

## EX-03–EX-04

`2*140ms + 160*1024*8/1,200,000 ~= 1.37s`. DNS/connection setup, origin time,
loss/congestion, decompression/parsing, CPU scheduling, rendering, and cache state
are omitted. Field p75 supports population targets; five controlled runs support
a scoped regression; synthetic supports known journey monitoring; a trace supports
one causal path. None substitutes for all others.

## EX-05–EX-07

Northstar uses static `/sky-events`, streaming `/events/:id`, a static shell plus
client data for `/live`, and private request rendering plus one edit island for
`/staff/schedule`. Before streaming it knows existence, safe status/headers, cache
policy, event identity, and partial-error contract. Hydration inputs include
schedule/content version, subject-safe display data, locale/time zone, and stable
IDs; a mismatch is recorded and repaired rather than suppressed.

## EX-08–EX-10

The public key includes normalized method/host/path, approved content-changing
query, bounded language, encoding, and version. Tracking queries do not vary it.
Private requests bypass lookup/store and assert zero entries across two test
subjects. Bounded stale-on-error applies only to public versioned event text;
staff schedule and current live safety status fail closed.

## EX-11–EX-12

Native controls, named regions, stable focus, associated errors, visible freshness,
and reachable retry exist in every state. DOM assertions establish structure;
axe checks selected rules; keyboard/zoom checks interaction and reflow; an
assistive-technology path tests an actual accessibility representation. None
alone proves complete conformance.

## EX-13

Warm the route, record equal checkpoints, navigate 30 times, release the route,
and compare active listener/timer/request/detached-node counts and retainer paths.
The repaired pass condition returns owned resource counts to baseline and shows
no lifecycle-correlated retained growth; it does not assert a universal heap size.

## EX-14–EX-15

The map is optional, deferred, isolated, deadline-bound, provenance-locked, and
owned. A text/table alternative carries the core information. Slow and blocked
variants preserve the same route; the repair changes only dependency isolation.
The heading, event data, keyboard path, and fallback remain usable.

## EX-16

Pair identity, seed, input hash, route/work, device/network, toolchain, expected
useful result, and all non-target controls match. Freeze scenario, raw trial,
configuration, environment, and output hashes. The lab cannot prove field
percentiles, every browser/assistive technology, production CDN behavior, or compliance.

## EX-17

The browser continues a trace; the edge validates syntax, creates its span, and
the origin creates authoritative server work. Allowed fields are route template,
render mode, cache outcome, content version, coarse client class, and failure code.
Cookies, tokens, staff identity, search text, and sensitive full URLs are rejected.

## EX-18

Northstar keeps one deployable portal with modules/islands and a thin public-read
BFF; only public versioned work may move to edge. It rejects microfrontends because
independent delivery benefit is unproven. A different option is acceptable with
measured drivers, explicit authority, full costs, stable owners, coexistence,
rollback, decommissioning, dissent resolution, and reversal evidence.

## PESD 2.0 extension answer

A defensible answer covers offline and degraded client state, browser-storage lifecycle, third-party governance, AI-content transparency and provenance, edge residency, and energy/performance budgets. It distinguishes the
requirement, enforcement mechanism, evidence, and owner; keeps modeled and
measured results separate; and names the failed condition that would reverse
the decision. Different architectures are acceptable when their invariants,
evidence boundaries, migration, and residual risk are explicit.
